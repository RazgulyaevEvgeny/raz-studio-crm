# Учёт студии брендирования Разгуляев

Веб-приложение для сотрудников студии: заказы и ведомость, календарь с задачами, поручения от начальства, расходы офиса, закупка расходников, проекты и прайс.

Сайт работает на GitHub Pages, данные хранятся в Firebase (Google) в базе Firestore на бесплатном тарифе Spark. Фото сжимаются в браузере примерно до 300 КБ и тоже хранятся в Firestore, поэтому Storage и привязка карты не нужны. Можно прикреплять фото и PDF до 700 КБ, видео не поддерживается. Сотрудники входят по почте и паролю.

## Файлы

| Файл | Что это |
|---|---|
| `index.html` | Сама страница учёта |
| `firebase-bridge.js` | Связка страницы с Firebase и экран входа |
| `firebase-config.js` | Настройки вашего проекта Firebase (заполнить один раз) |
| `firestore.rules` | Правила доступа к базе: только вошедшие сотрудники |
| `storage.rules` | Правила для Storage, если когда-нибудь включите его (сейчас не используется) |

## Настройка Firebase (один раз, около 15 минут)

1. Откройте [console.firebase.google.com](https://console.firebase.google.com), нажмите «Создать проект», назовите его, например, `raz-studio`. Google Analytics можно выключить.
2. **Вход сотрудников.** Слева Security → Authentication → Get started → вкладка Sign-in method → Email/Password → включить → Save. Затем вкладка Users → Add user: добавьте почту и пароль для себя и каждого сотрудника.
3. **База.** Databases & Storage → Firestore Database → Create database → редакция Standard, регион `europe-west3 (Frankfurt)` → Start in production mode. Затем вкладка Rules: замените текст содержимым файла `firestore.rules` → Publish.
4. **Настройки для сайта.** Шестерёнка → Project settings → General → внизу «Your apps» → значок `</>` (Web) → назовите приложение → Register. Скопируйте значения из блока `firebaseConfig` в файл `firebase-config.js` вместо надписей «ВСТАВЬТЕ».
5. **Разрешить домен.** Authentication → Settings → Authorized domains → Add domain → `razgulyaevevgeny.github.io`.

## Публикация на GitHub Pages

Репозиторий → Settings → Pages → Source: Deploy from a branch → Branch: `main`, папка `/ (root)` → Save. Через минуту сайт откроется по адресу `https://razgulyaevevgeny.github.io/<имя-репозитория>/`.

## Новые сотрудники

Добавляются в Firebase: Authentication → Users → Add user. Удалить или сменить пароль можно там же.

## Сколько места

Бесплатно Firestore даёт 1 ГБ. Записи заказов почти не занимают места, основное — фото: примерно 3 000 сжатых фото. Если места станет мало, можно включить Storage (нужен тариф Blaze) и перенести файлы туда.

### Сервер ИИ (Cloudflare, воркер `raz-marketing`)

Переменные: `GEMINI_API_KEY` (Secret, бесплатно с aistudio.google.com), `FIREBASE_PROJECT` = `raz-studio-5a486`, `ALLOWED_ORIGIN` = `https://razgulyaevevgeny.github.io`, `IG_TOKEN` (Secret, токен Instagram). Привязки: Workers AI с именем `AI` (запасной ИИ и фоны для креативов), по желанию KV `IG_KV` (токен Instagram продлевается сам).

Инструкции агентов хранятся на сайте, поэтому код воркера обновлять больше не нужно — только если меняется сам сервер.

## Раздел Kaspi (воркер `kaspi-orders`)

Заказы магазина на Kaspi ведутся в отдельном разделе «Kaspi», в ведомость они не попадают. Данные лежат в Firestore, коллекция `kaspi_orders` (правило есть в `firestore.rules`).

| Вкладка | Что там |
|---|---|
| Упаковка | Новые заказы Kaspi Доставки. Кнопка «Отправить на передачу» ставит в Kaspi статус «Скомплектован», Kaspi формирует накладную |
| Передача | Заказы с накладной. Отметьте нужные и нажмите «Распечатать накладные»: они соберутся в один PDF по 4, 2 или 1 на листе A4 |
| На доставке | Когда заказан и когда доставят. Ожидаемая оплата (сумма за вычетом комиссии) стоит в календаре на день доставки |
| Продано | Выданные заказы по месяцам. История за все месяцы загружается из Kaspi один раз, кнопкой её можно загрузить заново. Сверху — удержания Kaspi: доставка по каждому заказу и комиссия в % |
| Товары | Карточки товаров из прайс-листа (кабинет → Управление товарами → скачать, загрузить сюда) и из заказов: цена, наличие, продано, себестоимость, прибыль с 1 шт. По коду товара Kaspi воркер проверяет цены других продавцов (раз в 6 часов, пока учёт открыт) и учёт предупреждает, если у конкурента дешевле |

Пока учёт открыт, активные заказы обновляются раз в 10 минут, кнопка «Обновить с Kaspi» проверяет сразу.

Код воркера: `kaspi-worker/worker.js` (Cloudflare → Workers → `kaspi-orders` → Edit code → Deploy). Переменные: `KASPI_TOKEN` (Secret, токен API из кабинета продавца Kaspi), `FIREBASE_API_KEY` (apiKey из `firebase-config.js`), `ALLOWED_EMAILS` (почты сотрудников через запятую).

## WhatsApp: уведомления клиентам (воркер `whatsapp-bot`)

Когда менеджер меняет статус заказа или переносит срок на более поздний, учёт просит воркер отправить клиенту сообщение в WhatsApp. Сообщение уходит, только если в заказе есть телефон. Заказы Kaspi пропускаются. Каждое сообщение отправляется один раз, отметка хранится в заказе (поле `waSent`). Пока воркер не настроен, учёт работает как раньше и ничего не отправляет.

| Когда | Шаблон | Текст шаблона (создать в кабинете Meta, категория Utility, язык Russian) |
|---|---|---|
| Новый заказ | `order_accepted` | Здравствуйте, {{1}}! Ваш заказ № {{2}} принят в работу. Ориентировочный срок готовности: {{3}}. Если появятся вопросы, пишите в этот чат. |
| Статус «Макет» | `order_design` | Здравствуйте, {{1}}! Макет по заказу № {{2}} готов. Менеджер пришлёт его на согласование в этом чате. |
| Статус «Производство» | `order_production` | Здравствуйте, {{1}}! Заказ № {{2}} передан в производство. Срок готовности: {{3}}. Мы напишем, когда всё будет готово. |
| Статус «Готов» | `order_ready` | Здравствуйте, {{1}}! Ваш заказ № {{2}} готов, можно забирать. Спасибо, что выбрали нас! |
| Срок перенесён позже | `order_delay` | Здравствуйте, {{1}}! К сожалению, заказ № {{2}} задерживается. Новый срок готовности: {{3}}. Приносим извинения за ожидание. |

{{1}} — клиент, {{2}} — номер заказа, {{3}} — срок, например «25 октября» или «23–25 октября».

Код воркера: `whatsapp-worker/worker.js` (Cloudflare → Workers → `whatsapp-bot` → Edit code → Deploy). Переменные: `WA_TOKEN` (Secret, постоянный токен WhatsApp Cloud API), `WA_PHONE_ID` (Phone number ID рабочего номера), `FIREBASE_API_KEY` (apiKey из `firebase-config.js`), `FIREBASE_PROJECT` = `raz-studio-5a486`, `ALLOWED_EMAILS` (почты сотрудников через запятую).
