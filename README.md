# Учёт студии брендирования Разгуляев

Веб-приложение для сотрудников студии: заказы и ведомость, календарь с задачами, поручения от начальства, расходы офиса, закупка расходников, проекты и прайс.

Сайт работает на GitHub Pages, данные хранятся в Firebase (Google) в базе Firestore на бесплатном тарифе Spark. Фото сжимаются в браузере примерно до 300 КБ и тоже хранятся в Firestore, поэтому Storage и привязка карты не нужны. Можно прикреплять фото и PDF до 700 КБ, видео не поддерживается. Сотрудники входят по почте и паролю.

## Файлы

| Файл | Что это |
|---|---|
| `index.html` | Сама страница учёта |
| `firebase-bridge.js` | Связка страницы с Firebase и экран входа |
| `firebase-config.js` | Настройки вашего проекта Firebase (заполнить один раз) |
| `firestore.rules` | Правила доступа к базе: только вошедшие сотрудники |
| `storage.rules` | Правила для Storage, если когда-нибудь включите его (сейчас не используется) |

## Настройка Firebase (один раз, около 15 минут)

1. Откройте [console.firebase.google.com](https://console.firebase.google.com), нажмите «Создать проект», назовите его, например, `raz-studio`. Google Analytics можно выключить.
2. **Вход сотрудников.** Слева Security → Authentication → Get started → вкладка Sign-in method → Email/Password → включить → Save. Затем вкладка Users → Add user: добавьте почту и пароль для себя и каждого сотрудника.
3. **База.** Databases & Storage → Firestore Database → Create database → редакция Standard, регион `europe-west3 (Frankfurt)` → Start in production mode. Затем вкладка Rules: замените текст содержимым файла `firestore.rules` → Publish.
4. **Настройки для сайта.** Шестерёнка → Project settings → General → внизу «Your apps» → значок `</>` (Web) → назовите приложение → Register. Скопируйте значения из блока `firebaseConfig` в файл `firebase-config.js` вместо надписей «ВСТАВЬТЕ».
5. **Разрешить домен.** Authentication → Settings → Authorized domains → Add domain → `razgulyaevevgeny.github.io`.

## Публикация на GitHub Pages

Репозиторий → Settings → Pages → Source: Deploy from a branch → Branch: `main`, папка `/ (root)` → Save. Через минуту сайт откроется по адресу `https://razgulyaevevgeny.github.io/<имя-репозитория>/`.

## Новые сотрудники и доступ

1. Firebase: Authentication → Users → Add user (почта и пароль). Удалить или сменить пароль можно там же.
2. Сотрудник один раз входит в учёт и видит экран «Ждём доступ».
3. Руководитель нажимает в учёте своё имя вверху (на телефоне: «Ещё» → «Сотрудники») и включает переключатель напротив его почты.

Правила `firestore.rules` пускают в базу только руководителя и отмеченных сотрудников; чужой человек, даже зарегистрировавшись, ничего не увидит. Там же кнопка «Скачать копию всей базы». Чтобы никто не мог сам завести себе вход: Firebase → Authentication → Settings → User actions → снять «Enable create (sign-up)».

## Корзина, история, копии

- Удалённый заказ 30 дней лежит в «Ведомость → Корзина», оттуда его можно вернуть. Удалить навсегда может только руководитель.
- В карточке заказа внизу «История изменений»: кто и когда менял статус, сумму, оплату, срок.
- Каждую ночь бот сохраняет копию всей базы в `C:\RAZ\whatsapp-bot\backup` (30 последних дней) и пишет об этом в Telegram.
- Старые закрытые заказы Kaspi (старше 60 дней) учёт сам собирает в архивные документы по месяцам, чтобы не тратить бесплатный лимит чтений Firebase. В разделе Kaspi и аналитике они видны как раньше.

## Сколько места

Бесплатно Firestore даёт 1 ГБ. Записи заказов почти не занимают места, основное — фото: примерно 3 000 сжатых фото. Если места станет мало, можно включить Storage (нужен тариф Blaze) и перенести файлы туда.

### Отдел на автопилоте (вкладка «Отдел»)

Каждый понедельник в 08:00 по Павлодару агенты сами, без участия людей: аналитик делает сводку продаж по услугам (неделя, 30 и 90 дней), разведчик ищет свежие тренды Reels через поиск Google, генератор придумывает 8 идей (учитывает «Копилку трендов»), SMM-менеджер собирает 3–4 публикации на неделю, сценарист расписывает каждую: 5 хуков и 3 варианта съёмки. Ролики появляются в календаре, остальные идеи — в «Справочник → Идеи», сводка и тренды — во вкладке «Отдел». Там же кнопка «Запустить отдел сейчас». Всё бесплатно (Gemini, Cloudflare, Firebase).

Что включить один раз в Cloudflare → воркер `raz-marketing`:

1. Edit code → вставить новый `marketing-worker/worker.js` → Deploy.
2. Settings → Variables and Secrets → добавить секреты `AGENT_EMAIL` и `AGENT_PASSWORD`: почта и пароль сотрудника с доступом в учёт (можно взять вход бота Ани из `whatsapp-bot/.env`). Без них работает только кнопка.
3. По желанию секрет `TELEGRAM_BOT_TOKEN` (тот же, что у бота Ани) — итог недели придёт всем, кто подписан на бота в Telegram.
4. Settings → Triggers → Cron Triggers → Add → `0 3 * * 1` (это понедельник 08:00 по Павлодару). Если воркер выкладывается через `wrangler deploy`, расписание уже записано в `wrangler.toml`.

Инструкции агентов отдела можно переопределить в документе `marketing/agents` полями `d_analyst`, `d_ideas`, `d_smm`, `d_writer`.

**Маркетолог Саша** — виджет на главной учёта рядом с Аней. Показывает сводку аналитика из последнего запуска отдела, ближайшие ролики контент-плана (по нажатию открывается карточка на сайте маркетинга), число новых идей и трендов. В чате Саша отвечает от имени главного маркетолога: видит прайс, продажи по услугам, календарь и итоги отдела (воркер `raz-marketing`, путь `/api/sasha`, бесплатный Gemini). Переписка хранится в браузере. Чтобы чат заработал, вставьте в Cloudflare свежий `marketing-worker/worker.js`.

## Раздел Kaspi (воркер `kaspi-orders`)

Заказы магазина на Kaspi ведутся в отдельном разделе «Kaspi», в ведомость они не попадают. Данные лежат в Firestore, коллекция `kaspi_orders` (правило есть в `firestore.rules`).

| Вкладка | Что там |
|---|---|
| Упаковка | Новые заказы Kaspi Доставки. Кнопка «Отправить на передачу» ставит в Kaspi статус «Скомплектован», Kaspi формирует накладную |
| Передача | Заказы с накладной. Отметьте нужные и нажмите «Распечатать накладные»: они соберутся в один PDF по 4, 2 или 1 на листе A4 |
| На доставке | Когда заказан и когда доставят. Ожидаемая оплата (сумма за вычетом комиссии) стоит в календаре на день доставки |
| Продано | Выданные заказы по месяцам. История за все месяцы загружается из Kaspi один раз, кнопкой её можно загрузить заново. Сверху — удержания Kaspi: доставка по каждому заказу и комиссия в % |
| Товары | Карточки товаров из прайс-листа (кабинет → Управление товарами → скачать, загрузить сюда) и из заказов: цена, наличие, продано, себестоимость, прибыль с 1 шт. По коду товара Kaspi воркер проверяет цены других продавцов (раз в 6 часов, пока учёт открыт) и учёт предупреждает, если у конкурента дешевле |

Пока учёт открыт, активные заказы обновляются раз в 10 минут, кнопка «Обновить с Kaspi» проверяет сразу.

Код воркера: `kaspi-worker/worker.js` (Cloudflare → Workers → `kaspi-orders` → Edit code → Deploy). Переменные: `KASPI_TOKEN` (Secret, токен API из кабинета продавца Kaspi), `FIREBASE_API_KEY` (apiKey из `firebase-config.js`), `ALLOWED_EMAILS` (почты сотрудников через запятую).

### Посылки из Китая (вкладка «Kaspi → Из Китая»)

Заказы с 1688, Pinduoduo и Taobao от продавца до карго в Павлодаре. Вкладка только для отслеживания. Этапы как в приложении карго: заказали → отправлена → покинула Китай → прошла таможню → готова к выдаче → забрали. Кнопка на строке переводит посылку на следующий этап с сегодняшней датой.

- **Когда придёт.** Считается от даты текущего этапа по обычным срокам (≈19 дней от заказа). Когда наберётся 2+ посылки с датами, сроки каждого этапа берутся по вашим посылкам (медиана). Дата стоит в календаре учёта; готовая посылка висит в календаре на сегодня, пока её не заберут. В карточке есть кнопка «В календарь телефона» (.ics).
- **Сколько стоит карго.** Вес × тариф ₸/кг (тариф, название карго и курс юаня — сверху на вкладке) + доплата. Сумму можно вписать вручную. Сверху: карго за месяц, кг и средняя цена за кг.
- **Только для отслеживания.** Посылки никуда не попадают: ни в ведомость, ни в закупки, ни в аналитику, ни в карточки и прогноз товаров Kaspi. Закупки и себестоимость вписываются вручную, как раньше.
- **Аня в Telegram** (бот на рабочем компьютере, раз в 5 минут с 8:00 до 22:00): пишет, когда посылка сменила этап, когда задерживается против расчётной даты и если готовая посылка лежит в карго 2+ дня. Аня знает посылки и в ответах на вопросы.

- **L7 Cargo сам** (`whatsapp-bot/l7.js`): бот входит в кабинет l7cargopvl.kz по телефону и паролю (`L7_PHONE`, `L7_PASSWORD` в `.env` бота) и раз в 15 минут забирает этапы («Выехал из Китая», «Прошел таможенный пост», «Готов к выдаче»), вес и сумму карго в посылки учёта по трек-номеру. Посылки, которые есть только в L7, заводятся в учёт (выданные больше недели назад — сразу «Забрали»); трек-номера, вписанные только в учёт, добавляются в кабинет L7. «Забрали» отмечается в учёте вручную. Время последней сверки — на вкладке.

Посылки хранятся в `kaspi_orders` с `kind: 'parcel'`, правила базы менять не нужно.

## WhatsApp-бот (папка `whatsapp-bot`)

Бот работает на рабочем компьютере с Windows и подключается к рабочему WhatsApp как связанное устройство, так же как WhatsApp Web: один раз сканируете QR-код телефоном. Приложение на телефонах менеджеров остаётся как было, бот пишет в тех же чатах. Это неофициальный способ (библиотека Baileys): он бесплатный, но WhatsApp может заблокировать номер, если сочтёт его поведение спамом. Поэтому бот только отвечает тем, кто написал сам, и шлёт уведомления по заказам, с паузой «печатает…» и не чаще одного сообщения в 3 секунды.

Что умеет (кроме описанного ниже): в рабочее время ждёт менеджера 7 минут, вечером, в обед и в выходные отвечает через минуту и говорит, когда ответит Милана; после включения компьютера отвечает всем, кто ждал до 3 дней, с извинением; смотрит фото клиента (Gemini) и присылает примеры работ из «Прайс → Примеры работ для Ани»; если клиент обсуждал заказ и замолчал на сутки, один раз напоминает о себе (не больше 10 в день, только в рабочее время); через 2 дня после «Выдан» просит отзыв в 2ГИС; раз в 6 часов проверяет цены конкурентов на Kaspi и пишет в Telegram; если бесплатный лимит Gemini кончился, отвечает через запасной ИИ Cloudflare (воркер `raz-marketing`, если там задан `ALLOWED_EMAILS`, добавьте почту бота). Полная переписка хранится в `wa_log` по месяцам.

- **Уведомления о заказах.** Когда менеджер меняет статус заказа или переносит срок позже, учёт кладёт задание в коллекцию `wa_outbox`, а бот отправляет клиенту сообщение. Только если в заказе есть телефон, заказы Kaspi пропускаются. Каждое сообщение уходит один раз (отметка в поле заказа `waSent`). Если компьютер был выключен, задания ждут до недели. Тексты — константа `NOTICES` в `whatsapp-bot/brain.js`.
- **ИИ-консультант** на бесплатном Google Gemini (как в отделе маркетинга) отвечает на входящие: цены из «Прайса», заказы клиента по его номеру, стандартный срок (2–3 дня, кроме вышивки), оформляет заказ со статусом «Новый» и пометкой «Оформлено ИИ-ботом, проверить», зовёт менеджера. Если менеджер написал клиенту сам, бот молчит в этом чате 30 минут после его последнего сообщения, потом снова отвечает на новые вопросы (в том числе после вызова менеджера). На сообщения, пришедшие пока компьютер был выключен (старше 30 минут), бот сам не отвечает. Сообщения не отмечаются прочитанными. Переписка хранится в Firestore, коллекция `wa_chats`.
- **Виджет «Менеджер Анна»** на главной учёта. Бот (`whatsapp-bot/anna.js`) каждое утро с 9:00 и по кнопке «Обновить» готовит сводку: что было за сутки, кто ждёт менеджера, заказы от Анны на подтверждение и план на сегодня. Сводка лежит в `wa_anna/digest`, просьба обновить — `wa_anna/request`. Вопросы из поля «Спросить Анну» пишутся в `wa_anna_q`, бот отвечает в течение полминуты. Свежая сводка и ответы появляются, только когда рабочий компьютер включён.

Установка на рабочий компьютер:
1. Firebase → Firestore → Rules: вставить `firestore.rules` из репозитория и нажать Publish (нужны правила для `wa_chats`, `wa_outbox`, `wa_anna` и `wa_anna_q`).
2. Firebase → Authentication → Users → Add user: почта и пароль для бота. Это `BOT_EMAIL` и `BOT_PASSWORD`.
3. Для ИИ-ответов: aistudio.google.com → Get API key → Create API key (`GEMINI_API_KEY`, бесплатно, без карты). Если бесплатный лимит на день кончится, бот отвечает «передал менеджеру» и помечает чат. По желанию вместо Gemini можно включить платный Claude (`ANTHROPIC_API_KEY`).
4. Скачать репозиторий (GitHub → Code → Download ZIP), положить папку `whatsapp-bot` в `C:\RAZ\whatsapp-bot` (путь без русских букв).
5. Запустить `install.bat`. Он поставит Node.js (если нет), скачает компоненты, откроет `.env` для заполнения, включит автозапуск при входе в Windows и откроет страницу бота http://localhost:3777 с QR-кодом.
6. На телефоне: WhatsApp → Настройки → Связанные устройства → Привязка устройства → отсканировать код.

Дальше бот сам запускается в фоне при включении компьютера. Остановить — `stop.bat`. Журнал — `bot.log` в папке бота. Срок в заказах из WhatsApp (`ORDER_DAYS`) и сведения о студии (`STUDIO`) — в начале `whatsapp-bot/brain.js`; после правки запустить `install.bat` ещё раз.
